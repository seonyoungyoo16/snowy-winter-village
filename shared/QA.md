# 테마별 주민과 접속 알림 점검

## 가방(인벤토리) · 2026-11-07 (#61)

- `shared/village-bag.js`: 미니맵 아래 가방 버튼이나 I(한글 ㅑ)로 연다. 칸 30개, 같은 물건은 한 칸에 99개까지. 탭은 전체·먹거리·주운 것·꾸미기·소중한 것, 정렬은 종류순·많은 순·이름순.
- 공간마다 서울 날짜별로 주울 것이 새로 생긴다(겨울 22곳은 지역마다 고르게, 수족관·도서관 12곳). 모든 브라우저에서 같은 자리이고, 위로 걸어가면 자동으로 주워진다. 오늘 주운 자리는 다시 나오지 않는다. 겨울은 솔방울·눈꽃 결정·깃털·반짝 돌·겨울 열매, 수족관은 소라 껍데기·바다 유리, 도서관은 눌린 잎·헌 책갈피·별 비스킷.
- 먹거리는 먹을 수 있다(기운 나는 한마디와 하트 표정). 주운 것은 같은 것 3개를 조개껍데기 1개로 바꾼다(가게의 하루 한도 안). 가게에서 산 연·풍등·편지지는 꾸미기 탭에서 쓰기/빼기, 원정 카드·도감 그림·조개껍데기는 소중한 것 탭에 보인다.
- 가방은 이 브라우저에 남고 세 공간이 함께 쓴다. 핫바에 올리기는 이번에 넣지 않았다(핫바 칸이 고정이라 다음에 따로).
- 새 검사 `shared/check-village-bag.cjs`. `npm test` 153개 통과. 375×812에서 가방 버튼·주울 것·가방 창을 확인했다.

## 미니맵과 큰 지도 · 2026-11-07 (#60)

- `shared/village-map.js`: 오른쪽 위 둥근 미니맵(PC 132px, 휴대폰 104px)이 나를 따라가며 0.12초마다 다시 그린다. 미니맵을 누르거나 M(한글 ㅡ)을 누르면 화면 가득 지도가 열린다. 끌어서 옮기고, 휠·두 손가락·+/−로 확대하고, ◎로 내 자리로 돌아온다. M·Esc·×로 닫는다.
- 지도는 공간에서 바로 그린다: 벽과 바닥, 나무(작은 전나무), 건물(지붕 있는 블록), 길, 얼음 호수·연못, 지역과 장소 이름. 그 위에 나(바라보는 방향 화살표), 친구(이름), 이웃, 주민, 여기! 표시.
- 겨울에서는 가 보지 않은 곳이 눈안개에 덮이고 걸으면 반경 11m씩 걷힌다(4m 칸, 이 브라우저에 저장). 밝힌 등불을 누르면 바로 가고, 다른 곳을 누르면 걸어간다. 안개 낀 곳은 '아직 가 보지 않은 곳'이라고 알려 준다. 수족관·도서관은 안개 없이 전체가 보인다.
- 날씨 배지는 미니맵 아래로, 휴대폰의 지역 이름·등불 이동은 미니맵과 겹치지 않게 조금 아래로 옮겼다.
- 새 검사 `shared/check-village-map.cjs`. `npm test` 150개 통과. 1280×800에서 미니맵, M으로 연 큰 지도, 안개를 확인했다.

## 마을 이웃 NPC · 2026-11-07 (#59)

- `shared/village-folk.js`: 겨울 14명, 수족관·도서관 9명씩. 방문자와 같은 아바타 부품(동물·코트·목도리·장신구·키)을 조합해 서로 다르게 생기고, 이름과 성격(수다쟁이·느긋함·부지런함·몽상가·수줍음·호기심쟁이)이 있다. 겨울에서는 지역마다 나뉘어 산다.
- 정류장 세 곳을 돌며 걷고 쉰다. 위치는 서울 시각만으로 정해서 같은 방의 친구들에게 똑같이 보이고 따로 주고받지 않는다. 걸을 때는 길찾기 격자를 따른다(필요할 때 한 번 계산). 쉴 때는 가까운 이웃이나 다가온 나를 바라본다. 밤(23~6시)에는 3분의 1만 남는다.
- 성능: 가장 가까운 5명(28m 안)만 몸을 만들어 그린다.
- 가까이 가면(2.8m) 이름 말풍선이 뜨고, 누르면 대화 카드: 인사말, 대답 셋(반가워요/요즘 어때요/추천할 곳). 하루 한 번 대답하면 친해지고(처음 만남→아는 사이→친한 사이), 친한 사이가 되면 조개껍데기 1개를 한 번 준다. 이 브라우저에 남는다.
- 겨울 시장 거리에는 사흘마다·주말에 떠돌이 상인 바람이 온다. '구경할게요'를 누르면 마을 가게가 열린다.
- 새 검사 `shared/check-village-folk.cjs`. `npm test` 144개 통과. 1280×800 겨울 광장에서 이웃들이 걷고 쉬는 모습을 확인했다(콘솔 오류는 이전 탭 기록).

## 겨울 마을 넓히기 · 2026-11-07 (#58)

- 걸을 수 있는 땅을 ±25m에서 ±52m로 넓혔다. 땅 판·바깥 산·카메라 거리·내리는 눈(이제 사람을 따라 감싼다)도 함께 넓혔다. 길찾기는 같은 0.8m 격자를 쓰되 이진 힙과 탐색별 벽 캐시로 가장 먼 등불까지도 빠르게 찾는다.
- 방 규칙(배포된 Firebase 규칙)은 x·z를 ±26으로 막는다. 규칙을 바꾸지 않고 위치를 절반 크기로 보내고(`WIRE_SCALE=2`) 받을 때 두 배로 되돌린다. 마을 끝 ±52m가 정확히 ±26에 들어간다. 이 버전 이전의 브라우저와 섞이면 서로의 위치가 절반 자리에 보일 수 있다.
- `winter/districts.js`: 광장 둘레로 눈숲 오솔길(구불길·얼어붙은 개울과 다리·열매 덤불), 얼음 호수(넓은 얼음판·스케이트 자국·선착장·낚시 오두막), 등불 시장 거리(줄무늬 가판대 여섯·얼어붙은 분수·등불 줄), 전망 언덕(낮은 언덕·난간·망원경·깃발), 오두막 동네(오두막 다섯·울타리·우물). 광장과 지역을 밟힌 눈길로 잇고 길 위에는 나무를 두지 않는다. 모두 마을과 함께 한 번에 굽는다.
- 지역에 들어가면 위쪽에 이름이 잠깐 뜬다(처음엔 '새로운 곳'). 지역마다 등불 표지가 있고, 가까이 가면 밝혀진다. 밝힌 등불 옆에서는 '등불로 이동'으로 다른 밝힌 등불로 바로 간다. 방문·밝힘은 이 브라우저에 남는다.
- 새 검사 `winter/check-districts.cjs`. `npm test` 141개 통과. 1280×800에서 광장→눈숲 오솔길, 광장→등불 시장 거리를 직접 걸어 확인했다. 얼음 호수·전망 언덕·오두막 동네는 검사(길·소품·충돌)로만 확인했다.

## 화면 버튼과 마을 배치 정리 · 2026-11-07 (#56)

- 연·풍등·사진·던지기·코코아는 핫바에만 둔다. 원형 메뉴는 감정 6개, 여기!, 놀이, 동반 친구(부화 후), 함께 옮기기(가까울 때)만 남기고 이름을 늘 보여 준다. 오른쪽 아래 ☺ 버튼은 같은 원형 메뉴를 연다. 따로 떠 있던 카메라 버튼은 없앴다.
- `shared/radial-menu.js`에 공용 선 아이콘(`villageIcons`)을 두고 핫바·원형 메뉴·☺ 버튼이 함께 쓴다. 핫바는 아이콘 아래 짧은 이름을 보여 준다.
- `shared/village-tidy.js`: 핫바와 ☺ 버튼을 아래 조작줄의 안내 문구 바로 위로 옮겨 겹침을 없앴다. 처음 1.5m 넘게 걸으면 첫 안내 문구만 숨기고 새 안내는 그대로 보인다. 구석의 키보드·저장 안내는 8초 뒤 흐려진다(도움말에 같은 내용). 휴대폰에서는 부제목을 숨기고 장소 버튼을 작게, 공간 이동 두 버튼을 '다른 공간' 하나로 접는다.
- 주민 대화창은 '이야기 더 듣기' 아래 선물 주기·함께 놀기(수족관은 기증)만 보이고 나머지 7개는 '마을 일 더 보기'에 접는다. 카드는 불투명하게 해 뒤 버튼이 비치지 않는다.
- 겨울: 우편함·게시판·표지판 둘을 출발 지점 왼쪽 모닥불 옆에 모았다. 거울과 함께 꾸미는 마당은 서쪽 텃밭·토끼 우리 옆으로 옮기고, 마당은 나무 틀 위 판자 아홉 장으로 바꿨다. 큰 눈덩이·물놀이 공·책 수레는 출발 지점 앞을 가리지 않게 옆으로 옮겼다. 이미 옮겨 둔 브라우저는 저장된 자리를 쓴다.

## 원정·위치 핑·함께 옮기기·핫바 · 2026-11-07 (#39, #40, #42, #43)

- `shared/village-expedition.js`: 주민 대화의 '원정 보내기'. 함께 걷는 동반 친구(없으면 처음 부화한 친구, 그것도 없으면 주민의 종이학)를 눈 덮인 숲길·등대 바닷가·오래된 서고로 1·3·6시간 보낸다. 시작 시각만 저장해서 창을 닫아도 시간이 흐른다. 돌아오면 이야기 카드, 아직 도감에 없는 생물 그림(시작 시각으로 정해 운에 기대지 않음), 조개껍데기 2·4·6개(가게 하루 한도 안). 원정 중인 친구는 함께 걷기에서 빠졌다가 돌아오면 다시 따라온다. 실패는 없고 카드는 최근 6장.

- 수족관: 기존 빛이 낮 모습이고 밤에는 더 깊은 푸른빛. 바깥 날씨는 배지로만 표시한다.
- 도서관: 창밖 하늘 그림을 시간·날씨마다 다시 그린다(밤 별·달, 새벽·노을 해, 낮 하늘, 흐림·안개, 무지개). 비·큰비에는 유리와 창살 사이에 빗줄기 한 묶음(모바일 44개, 데스크톱 80개)이 내린다. 등불은 낮에 0.82로 약간 낮춘다.
- 인앱 브라우저 미리보기에서 `?sky=day&weather=heavy`, `?sky=dusk&weather=clear`(겨울), `?sky=day&weather=precip|rainbow|heavy`, `?sky=night`(도서관), `?sky=night&weather=precip`(수족관)을 확인했다. 콘솔 오류 없음. 낮 겨울에는 제목 그림자를 진하게 해 부제목을 읽을 수 있게 했다.
- 390×844에서 배지가 제목과 겹쳐 오른쪽 버튼 아래로 옮겼고, 가로 넘침이 없음을 확인했다. 실제 시각(서울 오전 10시)에서는 '낮 · 흐림'으로 표시되었다.
- 확인 범위 밖: 실제 휴대폰의 FPS, 3시간 경계에서의 실시간 전환 장면, 오프라인 단일 파일 `눈 내리는 겨울 마을.html`(게임 원본 `game.html`은 변경하지 않음).

## 방문 구분·기기·대략적인 지역 추가 · 2026-11-07

- Telegram 접속 알림에 첫 방문/재방문, 모바일/PC, IP 기반 국가·시도를 추가했다. Cloudflare가 제공하는 국가·1차 행정구역만 사용하며 도시·좌표·실제 IP는 보내거나 저장하지 않는다. 지역이나 기기를 알 수 없을 때는 확인 불가로 표시한다. 구버전 게임도 요청 헤더로 기기를 추정할 수 있다.
- `visitor_history`에 그룹별 익명 계정의 해시와 최초 관측 시각을 유지한다. 기존 최근 접속 기록을 이관했고, 별도의 24시간 중복 방지 정리로 재방문 기록을 잃지 않는다. 첫 전송 실패 후 재시도는 첫 방문을 유지한다. 사이트 데이터 삭제·브라우저/기기 변경·적용 전의 오래된 방문은 구분 한계가 있다.
- 모바일/PC 전달을 세 공간의 공통 클라이언트와 단일 HTML 전체에 반영했다. iPhone, Android 태블릿, 데스크톱 모드 iPad, Mac, Windows, 기기 정보 없음 등을 검사했다. 서버 검사 11개와 전체 `npm test`, Wrangler dry-run 통과. 기존 책·귤이·주민·공간 이동 검사도 통과했다.
- 실제 D1에 추가 테이블과 기존 기록 이관을 적용하고 Worker `59d68bd4-ed62-425b-a76c-bb85255fb6f9`를 배포했다. 실제 Firebase 임시 계정이 원래 겨울 마을 방에 `알림 점검`으로 기록한 뒤 배포 서버가 Telegram 전송 성공과 방문 기록 저장을 반환했다. 같은 접속의 두 번째 요청은 `already_received`로 억제했다. 시험 계정·자기 접속·자기 해시 기록만 정리했다.
- 실제 전송 검증 결과는 `.local-runs/arrival-enrichment-live.json`이다. 새 형식의 잠금 화면 배너·실물 모바일 자동 분류는 이번 자동 검사로 확인한 범위에 포함하지 않는다. 아래 실제 휴대폰 수신 확인은 앞선 알림 형식의 사용자 확인 기록이다.

## 실제 휴대폰 수신 확인 · 2026-11-07

- 최초 연결 QR 만료를 실제 상태 조회로 확인하고 봇 토큰 재입력 없이 일회용 연결값만 갱신했다. 연결 QR은 로컬에서 생성하고 유효 시간을 2시간으로 늘렸다. 만료된 QR과 링크는 설정 창에서 숨긴다. 설정 도구 구문 검사와 Worker 검사 7개 통과.
- 새 QR로 사용자가 휴대폰의 봇 대화에서 시작한 뒤 실제 `/health`의 `ready:true`, 설정 창의 연결 완료와 수신 대화 연결 여부를 확인했다. 대화 ID와 비밀값 원문은 출력하지 않았다.
- 공개 겨울 마을에 `책숲 토끼`로 실제 접속했다. 사용자가 휴대폰에서 해당 닉네임과 겨울 마을이 포함된 접속 알림 수신을 확인했다. 이어 수족관 → 도서관 이동 모두 연결됨을 확인했으며 알림 중복 방지 행은 1개를 유지했다. 세 공간 콘솔 오류 없음. 시험 게임 탭은 닫았다.
- 연결 완료 화면 `.local-runs/phone-telegram-linked.jpg`, 실제 공개 공간 이동 화면 `.local-runs/phone-arrival-world-travel.jpg`를 보관했다. 실제 PC 전원 종료와 휴대폰 잠금 화면 배너는 별도로 측정하지 않았다. 아래 준비 단계의 `ready:false` 기록은 연결 전 상태다.

## 게임 쪽 알림 연결 주소 설정 · 2026-11-07

- 세 공간 공통 `shared/arrival-config.json`에 실제 배포된 Worker 주소를 설정하고 단일 HTML 세 벌을 다시 빌드했다. `npm test` 전체 통과. 서버 비밀값은 HTML에 없으며 세 공간은 같은 친구 그룹의 확인된 입장만 요청한다.
- Worker의 세 비밀값 이름이 `secret_text`로 등록된 것을 공식 CLI에서 확인했다. 값은 읽거나 출력하지 않았다. 토큰 입력 뒤 설정 창은 `waiting_phone` 단계이며 실제 `/health`는 `ready:false`다.

- 공개 게임의 서버 주소 설정과 수신 계정 연결, 실제 폰 수신은 구분한다. 이 시점에는 최초 봇 시작과 실제 접속 알림 수신 확인을 기다린다. 준비 전 요청은 게임 입장을 막지 않고 제한된 재시도 후 조용히 끝난다.

## 알림 서버 실제 배포 · 2026-11-07

- 본인 승인 후 공식 Wrangler OAuth를 연결했다. 실제 배포에는 `account:read`, `user:read`, `workers_scripts:write`, `d1:write`, `offline_access`를 사용한다. 이름이 비슷한 `workers:write`만으로는 배포 API가 거부되어 `workers_scripts:write`로 바로잡았다. 인증 값은 OS 키링으로 보관하며 저장소에 넣지 않는다.
- Cloudflare의 전용 D1 `my-little-village-notifications`를 APAC에 만들고 세 테이블을 실제 생성했다. 다른 프로젝트와 Firebase 규칙·요금제는 변경하지 않았다.
- `my-little-village-arrivals.seonyoungyoo16.workers.dev` 배포 성공. 업로드 8.65KiB, 시작 시간 1ms. 실제 `/health` HTTP 200, 게임 출처의 사전 요청 HTTP 204와 정확한 CORS 출처 확인.
- 실제 Firebase 프로젝트에서 임시 익명 계정을 만들어 서버 측 신원 조회와 최근 입장 기록 확인이 같은 토큰으로 성공하는지 검증했다. 임시 방의 자기 접속 기록과 시험 계정 삭제도 확인했다. 원래 친구 방에 시험 캐릭터를 넣지 않았다.
- 위 확인 시점에는 Telegram 비밀값과 개인 수신 대화 연결 전이므로 `/health`는 `ready:false`다. 실제 폰 수신 완료로 해석하지 않는다. 토큰은 루프백 전용 입력창에서 직접 받아 Worker secrets로 전달한다.

2026-11-07 로컬 확인. 실제 배포·휴대폰 수신은 아래 로컬 결과와 구분한다.
