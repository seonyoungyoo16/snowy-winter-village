## 경쟁 없는 대회: 함께하는 목표·사진 주제 · 2026-11-07 (#15, 검토 이슈)

- 설계 선택: 순위 대회 대신 **친구 그룹이 함께 채우는 주간 목표**와, 사냥 대신 **오늘의 사진 주제**로 했다.
- 주간 목표(한국 기준 주마다 바뀜): 물고기 20마리 / 바다 수조 사진 12장 / 주민 부탁 10개. 각자 자기 주간 기록만 쓰고(`village/{party}/goals/w{주}-{uid}`), 화면에는 전체 합계와 함께한 친구 이름(가나다순)만 보인다. 개인 수·순위는 표시하지 않는다. 달성하면 한 번 알리고 일기에 적는다.
- 오늘의 사진 주제(날마다 다섯 하늘 중 하나): 맑은 낮·밤·비·새벽/노을·흐림/안개. 그 하늘에서 수족관 바다 수조 사진을 찍으면 하루 한 번 완성, 일기에 적는다.
- 주민 대화의 '함께하는 목표'로 연다. 새 규칙(세 파일 동일, 미배포): 기록 키가 자기 uid로 끝나야 하고 본인만 고칠 수 있으며 숫자 0–500. 배포 전에는 이 브라우저 기록만 더해진다고 안내한다.
- `shared/check-village-goals.cjs`: 주간·일간 순환, 실제 낚시 훅으로 내 기록 증가, 여러 친구 합계·이름만·다른 주 제외, 개인 수·순위 미표시, 달성 한 번·일기, 사진 주제 하늘 조건·하루 한 번, 규칙 구조, 세 공간 대화 선택지.
- 브라우저 확인 범위 밖: 목표 창은 검증된 창 스타일 재사용.

## 주민 평일·주말 일과표 · 2026-11-07 (#3)

- 주민마다 근무(원래 자리)·휴식(두 번째 자리)·잠(밤) 세 가지 일과를 한국 시간 평일·주말 표로 정했다. 자정을 넘는 밤 일과는 전날 표에서 이어진다. 휴식 자리: 밤이 모닥불 옆 (-7.6,-0.4), 해리 해파리 쉼터 앞 (12.5,2.5), 소담 창가 (6.2,-13.5).

- `shared/check-residents.cjs` 추가 검사: 일주일 30분 간격 모든 시각에 일과가 있음, 세 가지 일과가 모두 나옴, 목요일과 토요일 일과가 다름, 휴식 자리가 가구·입구와 겹치지 않음, 목요일 20시 실제 tick으로 휴식 자리 이동과 충돌 영역 이동, 이동 후에도 방문자를 따라가지 않음, 쉬는 동안 모든 활동 장소 경로 유지, 쉬는 주민과 대화 가능, 새벽 2시 잠든 자세, 다음 날 10시 30분 근무 자리 복귀.

- 인앱 브라우저에서 `?routine=rest`(겨울 모닥불 옆), `?routine=sleep&sky=night`(도서관 창가) 확인. 콘솔 오류 없음.

- `shared/check-sky-weather.cjs`: 시각·구간 경계, 같은 3시간 구간의 동일 날씨, 60일 480구간에서 다섯 날씨가 모두 나오고 한 종류가 45%를 넘지 않음, 무지개는 낮에 비가 그친 직후에만 뜸, 공간별 이름(겨울 '눈', 도서관 '비', 수족관 '바깥 · …')을 검사한다.
- 같은 검사가 실제 Three.js 장면으로 밤→정오 전환 시 배경·반구광이 낮 값에 도달하고 창문 유리가 밝기 0.6으로 낮아지는지, 바깥 안개는 짙어지지만 실내(`indoor`)는 안개 농도가 그대로인지 확인한다. 세 배포 HTML에 모듈·공간별 설정·tick 호출이 들어가고 자리표시자가 남지 않는지도 확인한다.
- 겨울: 기존 라벤더 저녁이 밤 모습이고 낮에는 옅은 겨울 하늘색. 눈송이 수는 날씨에 따라 15~100%, 함박눈은 1.3배 빠르고 바람 방향으로 흘러가며 경계에서 반대편으로 돌아온다. 낮에는 달을 숨기고 창문·가로등 유리를 어둡게 한다.
- 수족관: 기존 빛이 낮 모습이고 밤에는 더 깊은 푸른빛. 바깥 날씨는 배지로만 표시한다.
- 도서관: 창밖 하늘 그림을 시간·날씨마다 다시 그린다(밤 별·달, 새벽·노을 해, 낮 하늘, 흐림·안개, 무지개). 비·큰비에는 유리와 창살 사이에 빗줄기 한 묶음(모바일 44개, 데스크톱 80개)이 내린다. 등불은 낮에 0.82로 약간 낮춘다.
- 인앱 브라우저 미리보기에서 `?sky=day&weather=heavy`, `?sky=dusk&weather=clear`(겨울), `?sky=day&weather=precip|rainbow|heavy`, `?sky=night`(도서관), `?sky=night&weather=precip`(수족관)을 확인했다. 콘솔 오류 없음. 낮 겨울에는 제목 그림자를 진하게 해 부제목을 읽을 수 있게 했다.
- 390×844에서 배지가 제목과 겹쳐 오른쪽 버튼 아래로 옮겼고, 가로 넘침이 없음을 확인했다. 실제 시각(서울 오전 10시)에서는 '낮 · 흐림'으로 표시되었다.
- 확인 범위 밖: 실제 휴대폰의 FPS, 3시간 경계에서의 실시간 전환 장면, 오프라인 단일 파일 `눈 내리는 겨울 마을.html`(게임 원본 `game.html`은 변경하지 않음).

## 알림 서버 실제 배포 · 2026-11-07

- 본인 승인 후 공식 Wrangler OAuth를 연결했다. 실제 배포에는 `account:read`, `user:read`, `workers_scripts:write`, `d1:write`, `offline_access`를 사용한다. 이름이 비슷한 `workers:write`만으로는 배포 API가 거부되어 `workers_scripts:write`로 바로잡았다. 인증 값은 OS 키링으로 보관하며 저장소에 넣지 않는다.
- Cloudflare의 전용 D1 `my-little-village-notifications`를 APAC에 만들고 세 테이블을 실제 생성했다. 다른 프로젝트와 Firebase 규칙·요금제는 변경하지 않았다.
- `my-little-village-arrivals.seonyoungyoo16.workers.dev` 배포 성공. 업로드 8.65KiB, 시작 시간 1ms. 실제 `/health` HTTP 200, 게임 출처의 사전 요청 HTTP 204와 정확한 CORS 출처 확인.
- 실제 Firebase 프로젝트에서 임시 익명 계정을 만들어 서버 측 신원 조회와 최근 입장 기록 확인이 같은 토큰으로 성공하는지 검증했다. 임시 방의 자기 접속 기록과 시험 계정 삭제도 확인했다. 원래 친구 방에 시험 캐릭터를 넣지 않았다.
- 위 확인 시점에는 Telegram 비밀값과 개인 수신 대화 연결 전이므로 `/health`는 `ready:false`다. 실제 폰 수신 완료로 해석하지 않는다. 토큰은 루프백 전용 입력창에서 직접 받아 Worker secrets로 전달한다.

## 테마별 주민으로 변경한 버전 · 2026-11-07

- 겨울의 곰 주민 밤이, 수족관의 수달 사육사 해리, 도서관의 토끼 사서 소담을 별도 모델·의상·작업 도구·대사·장소로 구분했다. 입구에서 동일 캐릭터가 따라 바라보고 반복 인사하던 구현을 제거했다.
- `shared/check-residents.cjs`는 실제 빌드 HTML을 세 공간의 충돌 지도와 함께 실행한다. 72초 동안 방문자 위치와 친구 목록을 바꾸며 주민 위치·몸 방향이 따라가지 않고 대화나 손 흔들기가 자동 시작되지 않는지 검사한다. 기존 가구와의 발 위치, 활동 동선, 입장 인원 분리, 가까이에서 요청할 때만 열리는 대화도 검사한다.
- 실제 3D 찻잔 들기·수조 안에 떨어지는 먹이·얼굴에서 떨어진 책과 책장 넘기기를 검사한다. 주민·도구·주변 소품은 테마마다 합계 14개 이하의 메시/입자 그리기로 제한한다. 실물 휴대폰 FPS 측정은 별도다.
- `npm test` 통과. 마지막 사서의 책 위치·안내 표지 조정 뒤 세 테마 주민 검사와 전체 도서관 검사도 통과했다. 책장 선택·의자 독서·귤이 교감·공간 이동 등 기존 검사도 유지한다.
- IAB의 임시 친구 그룹에서 겨울 → 수족관 → 도서관 이동 후 각 주민에게 다가가 실제 대화 열기·닫기 확인. 겨울은 오두막 앞, 수족관은 산호 수조 옆, 사서는 기존 책상 뒤에 보인다. 수족관과 도서관 콘솔 오류 없음.
- 도서관 390×844에서 사서에게 책상 너머로 말 걸기, 역할 소개, 이야기 더 듣기, 닫기 확인. 사서 얼굴과 겹치던 책갈피 안내 표지를 옮겼다. 저장 화면은 `.local-runs/themed-winter-resident.jpg`, `themed-aquarium-resident.jpg`, `themed-library-resident-mobile.jpg`다.

## 이전 공통 NPC와 알림 서버 준비 기록

2026-11-07 로컬 확인. 실제 배포·휴대폰 수신은 아래 로컬 결과와 구분한다.

- `npm run build`, `npm test` 통과. 세 HTML의 공통 NPC 삽입, 단일 파일 유지, 친구 그룹·세 공간 주소 유지 확인.

- 알림 클라이언트 검사: 설정이 비었을 때 무요청, 실제 입장 기록 성공 이후에만 요청, 지정 친구 그룹 제한, 중복·세계 이동·실패 재시도, 공개 비밀값 배제.

이 문서만으로 클라우드 배포 완료나 휴대폰 수신 완료를 주장하지 않는다. 실제 PC 전원 종료나 실물 휴대폰 알림 배너는 로컬 자동 검사로 검증하지 않았다.
