# 물결 수족관

친구와 함께 천천히 거니는 작은 3D 수족관. 겨울 마을에서 사용한 캐릭터·이동·초대 방식으로 만든 별도 테마입니다.

- 바닥 터치 이동, WASD·방향키 이동, 드래그 시점 회전, 부드러운 3인칭 카메라
- 바다 토끼·조개 곰·산호 여우 선택과 닉네임 로컬 저장
- 큰 바다 수조의 물고기·바다거북·가오리와 사진 찍기, 산호 정원 먹이 주기, 해파리 쉼터에 앉기, 친구에게 손 흔들기
- 같은 초대 주소에서 최대 4명 캐릭터와 움직임 공유
- 친구 입장 게임 알림과 선택형 데스크톱 알림
- 점수·과제·경쟁 없이 이용하며 외부 모델·이미지·AI API를 사용하지 않습니다.

## 이용

배포 주소: https://seonyoungyoo16.github.io/little-blue-aquarium/

입장한 뒤 오른쪽 위 **친구 초대 → 초대 주소 복사**를 누르고 친구에게 주소 전체를 보내세요. 각자 기본 주소로 들어오면 서로 다른 방이 생성됩니다.

하단 **산호 정원**으로 이동한 뒤 **물고기 먹이 주기**, **해파리 쉼터**로 이동한 뒤 **앉아서 해파리 멍**을 선택합니다. 먹이 주기는 약 9초 동안 진행되며 언제든 중단할 수 있습니다. 손 흔들기와 먹이 주기·앉기 모습이 친구 화면에도 나타납니다.

**바다 수조 → 수조 사진 찍기**를 누르면 작은 3D 카메라를 양손으로 들고, 셔터가 한 번 반짝인 뒤 카메라 화면을 내려다봅니다. 약 6초 후 산책 상태로 돌아오며 **그만 찍기**나 이동으로 중단할 수 있습니다. 친구 화면에도 카메라·양손 자세·반짝임·사진 확인 자세가 나타납니다. 손 흔들기는 별도의 친구 인사 행동입니다.

`photo-action.js`가 카메라 소품과 촬영 자세를 처리합니다. 기존 데이터베이스 규칙의 `m: sled` 값을 수족관의 촬영 행동으로 해석하고 `b: 0~0.7`로 진행을 전송합니다. 겨울 마을은 별도 방 경로를 사용합니다. 서버 규칙 변경 없이 친구 화면이 받은 진행에 맞춰 동작을 재생하며, 뒤늦게 접속한 친구에게 지난 셔터를 반복하지 않습니다.

데스크톱 알림은 친구 초대 창에서 직접 켜고 브라우저 권한을 허용해야 합니다. 게임 탭이 열려 있을 때만 작동합니다. 탭을 닫은 뒤 받는 푸시 알림은 구현하지 않았습니다.

## 소스와 빌드

`물결 수족관 - 친구와 함께.html`은 Three.js, Firebase 브라우저 SDK, 폰트를 모두 포함한 배포용 단일 파일입니다. 멀티플레이에는 인터넷 연결이 필요합니다. `docs/index.html`이 GitHub Pages 배포 대상입니다.

```sh
npm ci
npm run build
npm test
npm run preview
```

로컬 미리보기는 http://127.0.0.1:4187 입니다. `npm run test:live`는 Firebase에 독립적인 임시 익명 계정 두 개와 임시 방을 만들어 보안 규칙과 동기화를 확인하고 자신의 시험 데이터만 정리합니다.

- `aquarium.js`: 도형 기반 장면·캐릭터·행동·충돌·길찾기·카메라
- `multiplayer.js`: Firebase 입장·캐릭터 보간·정리·알림
- `multiplayer.html`: 모바일 UI 템플릿
- `build-multiplayer.cjs`: 단일 HTML 생성
- `firebase-config.json`: 공개 프런트엔드 설정. 관리자 키는 포함하지 않습니다.

## 연결 범위

기존 `snowyroom-8a8a5` Firebase Spark 프로젝트의 익명 인증과 Realtime Database를 사용하며, 겨울 마을과 **동일한 프로젝트의 무료 할당량을 함께 사용합니다**. 새 유료 서비스는 추가하지 않았습니다. `database.rules.json`은 기존 규칙의 사본이며 이 테마 제작 중 서버 규칙을 변경하지 않았습니다.

수족관은 `aq_`로 시작하는 방 식별자를 사용합니다. 같은 친구 방의 겨울 마을 식별자 앞에 `aq_`를 붙여 대응하므로 공간을 이동해도 친구 그룹을 유지합니다. 각 공간의 좌표와 행동은 서로 다른 레코드에서 처리합니다. 서버에는 닉네임·캐릭터·좌표·행동·접속 시각을 전송합니다. 방 목록을 공개하지 않으며 익명 인증 후 해당 초대 주소의 방을 읽습니다. 자신의 캐릭터 레코드만 수정할 수 있습니다.

최대 4명은 정상 클라이언트의 입장 제한입니다. 악의적 클라이언트에 대한 서버 측 인원 제한은 아닙니다. 눈사람이나 겨울 마을 데이터는 가져오지 않습니다. 물고기와 해파리의 기본 유영은 각 브라우저에서 계산합니다. 친구의 먹이 주기 행동을 받아 각 화면에서 먹이와 물고기 모임을 표현하며 물고기 좌표 자체를 전송하지 않습니다.

모바일에서는 물고기·입자 수와 해상도를 줄입니다. 정적인 장식과 캐릭터 부품을 색상별로 합쳐 그리기 호출을 줄이고 실시간 그림자 맵은 사용하지 않습니다. 실제 휴대폰에서의 성능 수치는 별도로 확인해야 합니다.

## 겨울 마을과 왕복

입장 후 왼쪽 **겨울 마을 가기**로 건너갈 수 있습니다. 반대편의 **수족관 가기**로 돌아옵니다. 닉네임과 캐릭터 종류를 유지하며 목적지에 자동으로 입장합니다. 친구가 먼저 건너가면 이름과 **따라가기** 버튼이 나타납니다. 친구가 강제로 이동되지는 않습니다.

처음에는 같은 초대 주소로 접속하세요. 기존 초대 주소도 사용할 수 있고 이동 버튼이 같은 친구 방의 반대편 공간을 연결합니다. 세션 저장을 차단한 브라우저에서는 이름을 다시 입력해야 할 수 있지만 방 주소는 유지됩니다. 각 공간에서 새로운 활동을 시작하며 눈덩이 굴리기나 먹이 주기 도중의 동작은 이어서 재생하지 않습니다.

`world-travel.js`, `world-travel.css`, `world-travel.html`을 빌드 시 HTML에 포함합니다. 두 공간의 사용량은 같은 Firebase 프로젝트의 무료 할당량을 함께 사용합니다. 서버 규칙이나 유료 서비스를 추가하지 않았습니다.
