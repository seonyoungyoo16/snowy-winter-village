# 텔레그램 접속 알림

친구의 브라우저가 Cloudflare Worker에 접속을 기록합니다. 전날 방문 요약과 반복 접속 오류는 내 텔레그램 개인 대화로 받습니다. 주인의 PC와 게임 탭을 꺼도 동작합니다. 게임은 기존 GitHub Pages 주소에서 열립니다.

게임의 알림 서버 연결 주소는 루트 `shared/arrival-config.json`의 `endpoint`로 확인합니다. 빈 주소는 게임 쪽 비활성 상태입니다. 주소가 설정되어 있어도 서버 `/health`의 `ready`가 `true`여야 텔레그램 수신 대화 연결을 마친 상태입니다. 코드 검사 통과나 서버 배포만으로 실제 휴대폰 수신 완료를 뜻하지 않습니다.

알림 서버 주소는 `https://my-little-village-arrivals.seonyoungyoo16.workers.dev`입니다. 서버를 미리 배포해 두어도 봇과 수신 대화를 연결하기 전에는 알림을 보내지 않습니다. `/health`는 개인 정보 없이 연결 여부만 반환합니다.

게임 쪽 주소를 먼저 배포해 둘 수도 있습니다. 이 경우 최초 수신 계정을 연결하면 PC의 로컬 설정 창이 꺼져 있어도 이후 새 접속부터 클라우드 서버가 알립니다. 최초 계정 연결 QR과 링크만 발급 후 2시간 안에 사용해야 합니다.

## 최초 연결

1. 텔레그램에서 공식 **[@BotFather](https://t.me/BotFather)**를 열고 `/newbot`을 보냅니다. 표시 이름과 `bot`으로 끝나는 고유 사용자 이름을 정합니다. 발급받은 토큰은 채팅·GitHub에 올리지 않습니다.
2. 무료 [Cloudflare 계정](https://dash.cloudflare.com/)으로 로그인합니다. 유료 Workers 구독이나 Firebase Blaze 업그레이드는 필요하지 않습니다.
3. 이 폴더에서 `npm ci`를 실행합니다. Node.js 24 이상이 필요합니다.
4. `npx wrangler login --use-keyring --scopes account:read user:read workers_scripts:write d1:write`로 공식 CLI 연결을 승인합니다. Windows에서 키링 의존성 설치를 요청하면 공식 안내에 따릅니다. 계정 조회, Workers 배포, D1 저장소 권한을 사용합니다.
5. `npm run setup`을 실행하고 출력되는 `http://127.0.0.1:.../setup/...` 주소를 엽니다. 이 PC에서만 열리는 일회용 창입니다. 계정을 선택하고 봇 토큰을 **그 창의 비밀번호 입력란**에 붙여 넣어 연결합니다.
6. 휴대폰 카메라로 창의 QR을 찍거나 **내 텔레그램 봇 열기**를 눌러 내 휴대폰 텔레그램에서 **시작**합니다. 처음 연결한 개인 대화 하나만 수신자로 저장합니다. 연결 QR과 링크는 2시간 동안 유효하며 다른 사람에게 공유하지 않습니다.
7. 창에서 연결 완료를 확인한 뒤 루트에서 `npm test`를 실행하고, 갱신된 `shared/arrival-config.json`과 빌드 HTML을 기존 저장소에 배포합니다. 실제 주소에서 접속해 휴대폰 수신을 확인합니다. 연결을 마치면 로컬 설정 창과 명령을 종료해도 됩니다.

Worker 이름은 `my-little-village-arrivals`, D1 이름은 `my-little-village-notifications`입니다. 처음 Workers를 쓰는 계정에서 workers.dev 하위 도메인 설정을 요구하면 Cloudflare 대시보드에서 무료 하위 도메인을 먼저 정합니다. 다른 서비스에 쓰는 봇은 덮어쓰지 않습니다.

## 연결 QR이 만료됐을 때

아직 수신 대화를 연결하지 못했다면 기존 설정 명령을 종료한 뒤 이 폴더에서 `npm run setup -- --renew little_winter_village_bot`을 실행합니다. 다른 봇을 쓴다면 마지막 사용자 이름을 바꿉니다. 기존 Cloudflare 로그인·로컬 설정과 등록된 세 비밀값이 필요합니다.

이 명령은 봇 토큰을 다시 받거나 읽지 않고 일회용 연결값과 유효 시간만 갱신합니다. 새 창의 QR로 다시 **시작**합니다. 이미 수신 대화가 연결된 서버는 갱신하지 않으며 수신자를 바꾸지 않습니다. QR은 로컬에서 생성하고 gitignore된 `.local-runs/`에만 저장합니다. 게임 HTML과 Worker에는 QR 라이브러리를 포함하지 않습니다.

## 동작과 보관 정보

- 서버가 Firebase 로그인과 실제 입장 기록을 확인한 뒤 공유 친구 그룹의 겨울·수족관·도서관 방문을 기록합니다. 같은 공간에서 같은 사용자의 5분 이내 재접속과 이미 기록한 세션의 재전송은 한 건으로 셉니다. 서로 다른 공간 입장은 각각 셉니다.
- 한국 시간 오전 9시에 전날 0시부터 자정까지의 전체 방문자 수, 첫 방문·재방문 인원, 공간별 입장 횟수를 보냅니다. 방문자는 하루에 한 번씩 구분하고, 처음 들어온 날에 다시 입장해도 그날의 방문자 분류는 첫 방문입니다. 기록이 시작된 첫날에는 집계 시작 시각을 표시합니다.
- [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)는 UTC `0,10,20 0 * * *`에 실행합니다. 오전 9시 10분과 20분은 전송 실패 시 재시도에 쓰고, 날짜별 전송 표시로 중복을 막습니다. 이모지는 알림 제목에만 넣습니다.
- `visitor_history`의 친구 그룹·Firebase 익명 UID 해시와 최초 관측 시각으로 첫 방문 여부를 구분합니다. `visit_events`에는 공간, 세션·방문자 해시, 접수 시각을 기록합니다. 요약 작업 때 지난 7일보다 오래된 방문 행을 정리합니다. 방문 기록이 남은 기간부터 집계하고 브라우저 데이터를 지우거나 기기를 바꾸면 새 방문자로 보일 수 있습니다.
- 방문 브라우저가 오프라인이거나 요청을 차단하면 집계에서 빠질 수 있습니다. 방문 기록 요청은 최대 세 번 재시도하고 게임 입장과 별도로 처리합니다.
- 봇 토큰·웹훅 검증값·일회용 연결값은 **Worker secrets**로 보관합니다. 설정 도구는 CLI 표준입력으로 전달하고 토큰을 설정 파일에 쓰지 않습니다. 공개 게임에는 서버 주소와 친구 그룹 ID만 포함됩니다. 로컬 설정 파일과 Wrangler 상태는 gitignore 대상입니다.
- Telegram 봇을 차단하면 휴대폰 수신을 중단할 수 있습니다. 알림 요청도 중단하려면 공개 설정의 endpoint를 비운 뒤 다시 빌드·배포합니다. 서버와 저장소 삭제는 Cloudflare 대시보드에서 별도로 진행합니다.

## 관리자용 반복 접속 오류 알림

- 공유 친구 그룹의 세 공간에서 입장 등록·친구 동기화·상태 기록 오류와 20초 이상 완료되지 않은 연결 시도를 집계합니다. 한 연결 시도의 오류와 재전송은 한 건으로 셉니다. 일반 퇴장과 정원 초과는 별도로 처리합니다.
- 한 공간에 최근 5분 동안 5건 이상 들어오면 연결된 개인 텔레그램 대화에 공간 이름, 전체 실패 횟수, 닉네임·실패 단계·오류 코드별 횟수와 공간 열기 버튼을 보냅니다. 상세 항목은 빈도가 높은 12개까지 보여 주고 나머지는 합산합니다. 같은 공간의 다음 알림은 15분 뒤부터 가능합니다.
- Firebase 인증을 마친 브라우저의 보고를 사용합니다. 브라우저가 오프라인이거나 로그인 자체가 실패하면 집계에서 빠질 수 있습니다. 오류 기록에는 공간, 중복 확인용 해시, 접수 시각, 게임 닉네임, 실패 단계와 허용된 오류 코드를 남깁니다. 해당 공간의 다음 보고에서 24시간 지난 행을 지웁니다. 과거 기록이나 예전 게임에서 누락된 정보는 `미확인`으로 표시합니다.
- 기존 `connection_failures` 테이블을 쓰는 배포에서는 `connection-failure-details.sql`의 세 열을 먼저 추가합니다. 새 DB를 만들 때는 `schema.sql`에 세 열이 포함됩니다.

## 무료 한도

2026-11-07 공식 문서 확인 기준입니다. 무료 한도는 변경될 수 있으며 서비스 대시보드의 실제 사용량을 확인합니다.

| 서비스 | 무료 범위 | 이 기능에서 하는 일 |
| --- | --- | --- |
| [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/limits/) | 하루 100,000 요청, 요청당 CPU 10ms | 입장 확인과 Telegram 전송 |
| [Cloudflare D1](https://developers.cloudflare.com/d1/platform/pricing/) | 하루 500만 행 읽기·10만 행 쓰기, 전체 5GB | 중복 알림 방지·재방문 구분·수신 대화 저장 |
| [Telegram Bot](https://core.telegram.org/bots) | 봇 플랫폼 무료 | 휴대폰 알림 수신 |

Workers 한도는 사전 요청·상태 확인도 포함하므로 100,000명이 접속할 수 있다는 뜻은 아닙니다. D1 한도 역시 SQL이 실제 읽거나 쓰는 행 기준입니다. [Telegram 전송 제한](https://core.telegram.org/bots/faq)에 맞춰 한 대화로 약 1.1초 간격을 예약하며 한꺼번에 많이 접속하면 재시도합니다. 무료 한도 초과나 서비스 장애 시 알림이 실패할 수 있고, 자동 결제 업그레이드는 설정하지 않습니다.

## 확인 명령

`npm test`는 실제 SQLite 스키마로 한국 시간 날짜 경계, 첫 방문·재방문, 공간별 횟수, 중복 및 재시도, 오류 알림 형식을 검사합니다. 외부 Firebase/Telegram 호출은 대역입니다. 기존 서버를 갱신할 때는 `schema.sql`의 방문 테이블을 먼저 추가하고 `wrangler.local.jsonc`에 예제 설정의 `triggers`를 반영한 뒤 `npx wrangler deploy --config wrangler.local.jsonc`로 배포합니다. 공개 게임도 다시 빌드·배포합니다.

`npx wrangler deploy --dry-run --config wrangler.example.jsonc`는 묶음이 Workers에서 배포 가능한지 확인하며 외부 서버를 만들지 않습니다. 실제 배포는 로컬 설정 창에서 합니다. 알림 서버의 `/health`는 연결 여부만 반환하고 수신자나 비밀값을 반환하지 않습니다.
